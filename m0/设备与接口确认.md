# M0 设备与接口确认

目标是在本轮开始后1小时内完成M0。M0通过必须同时具备实物合规、所有模块供电与通信可用、一键启动路径明确、接口协议和实际版本记录。只有选型表、图纸或软件自测不能证明实物已通过。当前状态为进行中，实物证据待提供。

## 一小时的确认顺序

| 时间 | 硬件队友 | 机械队友 | 软件队友 |
| --- | --- | --- | --- |
| 0至10分钟 | 列实际设备型号、固件、电池与稳压参数 | 测无人机轴距、平台长宽、平台高度，检查全桨防护 | 核实际视觉板、操作系统、相机与可用串口 |
| 10至25分钟 | 核输入电压、逻辑电平、地线、驱动电流；断电核接线后分别通电 | 称全部机载载荷，核平台双圆十字及安装空间 | 确認相机能采集图像，读取飞控真实心跳或本地状态 |
| 25至40分钟 | 测电机及视觉板同时工作时是否掉压、重启 | 记录实物尺寸与重量证据 | 用联通工具分别验证车、机载板、笔记本局域网 |
| 40至50分钟 | 核飞控实际定位、控制接口和通信中断处理 | 核接口线固定与防护，整理测量值 | 核一键启动就绪条件、确认和重复包行为 |
| 50至60分钟 | 填供电与接口实测结果 | 填尺寸与防护结果 | 填固件和代码版本，逐条审计是否全部通过 |

## 接口协议 v0.1

应用层定义已写入代码并可验证。物理串口、电平、针脚、传感器协议和实际飞控固件尚未冻结，必须以实际型号核对后填写，不将候选针脚直接接到设备。

| 通路 | 当前设计 | 实机确认内容 |
| --- | --- | --- |
| 小车到机载任务控制器 | 离线局域网UDP；接收端端口14560 | 实际IP、Wi-Fi连接与丢包/时延 |
| 机载板到飞控 | 飞控支持的有线控制与遥测接口 | 实际协议、串口名称、波特率、电平、TX/RX/GND与供电规范 |
| 机车到地面站 | 地面站UDP端口14561接收实际遥测 | 实际IP、端口、防火墙及有效字段 |
| 主控到循线/编码器/驱动 | 按实物手册设计 | 引脚、输入输出电平与电机电源隔离/共地关系 |
| 主控到释放机构 | 一次性释放动作，由机载状态机授权 | 实际舵机电压、电流、信号与接口实现 |

所有UDP包为UTF-8 JSON，长度≤2048字节。共同字段为version=1、node（car/drone/ground）、session（本次任务唯一编号）、seq（发送方递增序号）、type、t_ms（该设备本地单调时钟毫秒）、payload。设备本地时钟不能直接跨设备相减计算单程延迟。

| 类型 | payload必填字段 | 用途 |
| --- | --- | --- |
| PING | 空对象 | 无动作的通信测试 |
| ACK | ack_seq、ack_type | 确認本次session内原始包；PING确认不表示飞行就绪 |
| READY | ready（布尔值） | 表示本节点启动条件是否满足 |
| START | mode（drop/dynamic） | 小车启动指令；只由car发送；实际动作执行器尚未实现 |
| TELEMETRY | valid（布尔值）、state | 实际遥测有效性及状态；定位无效时仍可发送，但标为无效 |

遥测扩展字段：x_m、y_m、z_m、vx_mps、vy_mps、yaw_rad、s_m、segment、battery_v、position_valid、target_valid。地图坐标以场地左下角为原点，x向右、y向上、z向上，单位m；飞控NED坐标需显式转换。s_m为车从起点行驶的实际路程。航向正方向统一为从+x向+y旋转，单位rad。

## 一键启动规则

1. 启动前车、机载板、飞控、定位与日志满足就绪条件。未就绪时保持未启动状态，不让车起步后等待人工修复。
2. 实际按钮触发后，车开始行进并发送同一session、seq和mode的START。重发不改变序号，不能因等待ACK让已启动的小车停车。
3. 机载程序以(session, seq)去重，同一启动只执行一次；任务运行中拒绝第二次新启动；机重启后不能凭旧START自动重新起飞。
4. 收到START的ACK只确认收到，不代表已起飞；飞行状态必须通过实际遥测确认。实际执行前还要核发送方、就绪状态及任务状态。
5. 动作程序用可靠就绪与任务状态约束投放、下降和再起飞。当前联通工具不执行飞控指令、不触发舵机，也不测试电机。

## 联通检查命令

在接收设备运行（Python3，无第三方依赖）：

```powershell
python m0/linkcheck.py listen --host 0.0.0.0 --port 14560 --duration 60
```

在另一设备发送无动作PING，将地址替换为接收端真实局域网IP：

```powershell
python m0/linkcheck.py probe --host 接收端局域网IP --port 14560 --node car --count 20
```

分别验证小车通信端、机载板和地面站。无法运行Python的ESP32端需实现相同PING/ACK字段；本工具不替代板端程序。日志至少记录测试设备、实际IP、包数、往返时延和通信是否成功。笔记本回环测试只验证软件收发，不能记为车机联通通过。
